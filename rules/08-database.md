# 数据库设计与迁移规则（08-database）

## 表结构设计

- 命名：表 snake_case 复数、字段 snake_case、主键 id、外键 xxx_id。
- 所有表包含 created_at / updated_at（按团队约定）；时间统一 UTC 存储、展示层转换。
- 字符集统一；金额用定点数，禁止浮点存钱。
- 约束完整：非空、唯一、外键按业务启用；逻辑删除按业务决定并统一字段名。
- 禁止存储可推导数据（冗余需评审并保证一致性）。

## 迁移流程

1. 所有结构变更以迁移脚本提交并走评审，禁止手工改库。
2. 脚本必须含回滚方案；破坏性变更（删列、改类型）先拆分兼容步骤。
3. 发布顺序：先兼容性迁移 → 发布代码 → 清理旧结构，避免停机。
4. 大表变更评估锁与耗时，低峰执行或使用在线变更工具。
5. 迁移先在测试环境验证，确认无数据丢失与性能回退。

## 索引与查询

- 为高频查询设计索引；联合索引遵循最左前缀；避免冗余索引。
- 禁止对索引列使用函数包裹或隐式类型转换。
- 复杂查询用 EXPLAIN 验证执行计划；禁止无 WHERE 的全表扫描上线。
- 慢查询纳入监控，超阈值必须优化或记录豁免原因。

## 备份与恢复

- 生产库定期自动备份，保留周期满足 RPO / RTO。
- 恢复演练至少每季度一次。
- 关键变更前可手动快照，误删依赖备份与归档日志。

## 数据字典

- 表与字段必须有注释；ER 图与数据字典随迁移更新并指定维护责任人。
- 敏感字段标注分类与脱敏要求。
