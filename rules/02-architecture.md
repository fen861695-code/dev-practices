# 架构与技术选型规则（02-architecture）

## 技术选型流程

1. 明确需求与约束：业务目标、规模预期、团队能力、时间与成本边界、合规要求。
2. 候选评估：按评估维度横向比较，输出对比表。
3. 小规模验证（POC）：对关键不确定性做最小原型验证。
4. 决策与记录：输出架构决策记录（ADR），未入选方案记录落选理由。

## 评估维度

- 团队熟悉度与学习成本（新引入需预留学习期）
- 生态与维护（社区活跃度、版本迭代、长期可维护性）
- 性能与扩展（量级预期、水平扩展能力与成本）
- 许可与合规（许可证类型、商用限制、数据主权）
- 可观测性（日志、指标、追踪接入成熟度）
- 招聘与人才可获得性

## 架构评审触发条件

- 新系统立项、核心模块重构、跨团队影响、引入重大新技术或新架构模式。
- 评审要点：模块边界与依赖方向、数据流与状态管理、故障模式与降级、演进性与扩展路径、安全与合规。
- 评审不通过不得进入编码阶段，结论必须记录。

## ADR 模板

背景（为什么需要决策）→ 决策（最终选择）→ 备选方案（落选理由）→ 理由（关键依据）→ 后果（正面 / 负面影响、迁移成本、何时重新审视）。
