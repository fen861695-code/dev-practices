# 文档规则（12-docs）

## README 模板

1. 项目简介：做什么、解决什么问题、目标用户。
2. 技术栈与环境要求（版本、依赖、端口）。
3. 本地启动步骤：安装、配置、运行、测试命令。
4. 目录结构说明。
5. 常用命令（lint、test、build、deploy）。
6. 文档入口：架构、API、运维手册链接。
7. 团队约定：如何提交代码、如何发版。

## API 文档

- 对外接口以 OpenAPI 维护，自动生成或注释同步。
- 包含：资源、方法、参数、请求响应示例、错误码、鉴权、限流。
- 接口变更必须同步更新文档，禁止漂移。

## 注释

- 注释解释"为什么"，不重复"做了什么"。
- 公共 API、复杂算法、非显然业务规则必须注释。
- 禁止保留被注释掉的代码块。
- TODO / FIXME 必须关联 issue 或负责人。

## CHANGELOG

- 按版本组织：新增、修复、变更、移除、安全。
- 可由 Conventional Commits 自动生成后人工校对；破坏性变更显著标注。
