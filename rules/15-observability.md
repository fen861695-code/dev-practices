# 可观测性与运维规则（15-observability）

## 结构化日志

- 全链路统一 traceId / requestId，跨服务透传。
- 日志采集到统一平台，按服务、级别、关键字可检索。
- 保留策略明确；错误日志包含足够上下文（请求、参数、堆栈）。

## 指标与监控

- 服务侧按 RED：请求速率、错误率、耗时；资源侧按 USE：利用率、饱和度、错误。
- 核心业务指标单独埋点，用于发布对比。
- 前端监控：JS 错误、接口失败率、核心 Web Vitals。

## 告警与值班

- 告警有阈值、持续时长与分级；禁止无效告警刷屏。
- 关键服务建立值班与响应流程，告警到人，响应时效按严重级约定。
- 告警规则定期回顾，误报与漏报纳入改进。

## 分布式追踪

- 跨服务调用接入分布式追踪，慢请求与错误按链路定位。
- 外部依赖（第三方 API、消息队列、数据库）纳入追踪。

## 事故响应

1. 发现异常先止血（回滚 / 降级 / 限流），再排查根因。
2. 按流程升级：值班工程师 → 技术负责人；重大事故同步管理者。
3. 事故后 24-72 小时输出复盘：时间线、根因、影响、改进项，跟进闭环。
4. 复盘聚焦流程与系统改进，不追究个人责任。
