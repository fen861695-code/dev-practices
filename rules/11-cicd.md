# CI/CD 与交付规则（11-cicd）

## CI 流水线（每次推送与合并主干自动触发）

1. 代码风格检查（Lint / 格式化）。
2. 单元测试与覆盖率统计。
3. 构建（前端打包、后端镜像构建）。
4. 静态安全扫描（SAST，如 CodeQL）与依赖漏洞扫描（SCA，如 Dependabot）。
5. 制品推送至制品库并标注版本。
6. 可选：部署测试环境并运行冒烟测试。

## 分支保护与门禁

- main / develop：要求 PR、要求检查通过、要求线性历史、禁止强制推送。
- CI 失败即门禁失败，禁止跳过；豁免需技术负责人书面确认。
- 依赖更新单独开 PR，自动检查冲突与测试。

## 环境管理

- dev：随时可重建，数据可丢弃。
- staging：与生产配置对齐（除真实密钥），跑冒烟与回归。
- production：受控发布，监控告警就绪，具备回滚预案。

## 发布策略

- 发布单包含：版本、变更、影响面、回滚步骤、监控项。
- 高流量服务优先灰度（金丝雀 / 蓝绿），逐步放量观察指标。
- 失败立即回滚或回退流量；回滚演练定期进行。
- 数据库变更与代码发布顺序协调：先兼容后发布、先发布后清理。

## 版本管理

- 语义化版本（主.次.修订），破坏性变更升主版本。
- 版本与 Git tag、制品、镜像标签一一对应，可追溯源码。
