# 后端 / API 规则（07-backend）

## 工程约束

- 统一 Lint + Formatter 并接入 CI；依赖锁定；禁止已知高危漏洞或停止维护的依赖。
- 运行时与依赖版本在文档 / 镜像中声明，环境可复现。

## API 设计（RESTful）

- 资源名词复数、路径小写以 - 分隔：/api/v1/users。
- 方法语义：GET 查询、POST 创建、PUT 全量更新、PATCH 局部更新、DELETE 删除。
- 状态码语义化：200 / 201 / 204 / 400 / 401 / 403 / 404 / 409 / 422 / 429 / 500 / 503。
- 版本走路径前缀（/api/v1），破坏性变更必须升版本。
- 列表接口统一分页（page / page_size 或游标），返回分页元信息。
- 统一错误响应：{ code, message, details }，code 业务码、message 可读、details 字段级信息。
- 认证统一方案（OAuth2 / JWT），鉴权在网关或中间件统一处理。
- POST 可携带幂等键；重试语义明确，避免重复下单、重复扣款。

## 错误处理

- 业务异常与系统异常分离；禁止空 catch 吞异常。
- 对外错误信息不得包含堆栈、SQL、内部路径。
- 未捕获异常由全局处理器收敛为结构化响应并告警。

## 日志

- 结构化 JSON 日志：时间、级别、服务、traceId、spanId、事件、关键字段。
- 级别：DEBUG / INFO / WARN / ERROR / FATAL；请求级日志中间件统一记录。
- 禁止记录敏感信息（密码、令牌、身份证、手机号、卡号），必须脱敏或加密。

## 数据 / 缓存 / 可靠性

- 表结构变更走迁移脚本（见 08-database）。
- 事务短小、锁粒度最小；敏感字段加密存储；慢查询纳入监控。
- 缓存键含业务域与版本，必须设置 TTL；写路径处理缓存一致性；防穿透 / 击穿 / 雪崩。
- 外部调用设置超时与重试（指数退避 + 抖动）并做好熔断降级；写操作幂等。
- 分布式事务优先"本地消息表 / 事务消息 + 最终一致"。
- 关键路径有功能开关，故障时快速止血。

## 安全

- 所有外部输入必须校验与清洗；认证与授权分离，默认拒绝。
- 密钥只存于密钥管理系统，禁止入库、入日志、入前端代码。
- 按 OWASP Top 10 定期自查；依赖与镜像定期扫描，高危限期修复。
