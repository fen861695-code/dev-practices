# 第 0 步：开始之前——认识软件开发、准备工具

> 本步目标：让小白理解"软件是怎么回事"，并把开发要用的工具装好、确认能运行。
> 默认项目主线：一个"待办清单"网站（能添加、查看、标记完成、删除待办事项）。

## 1. 进度（导师话术）

"我们还没开始写代码，这一步先搞清楚两件事：软件到底是怎么跑起来的，以及我们要用到哪些'厨具'。全程大概 30-40 分钟。"

## 2. 为什么

- 不理解全貌就动手，容易每一步都不知道自己在干嘛。
- 工具没装好，后面每一步都会卡住。所谓"工欲善其事，必先利其器"。

## 3. 概念扫盲（餐厅类比）

- **程序**：写给电脑看的"指令清单"，电脑会逐条照做。
- **前端**：餐厅的菜单、大堂、服务员——用户在浏览器里直接看到、点到的一切。
- **后端**：厨房——用户看不到，但真正处理逻辑、保存数据的地方。
- **数据库**：厨房的冰箱和仓库——数据（比如待办事项）长期存放的地方。
- **接口（API）**：菜单和点单方式——前端按"菜单"向后端点单，后端照单处理。
- **一次完整访问**：顾客（浏览器）照着菜单（接口）点菜（发请求）→ 服务员把单子传到厨房（后端）→ 厨房从冰箱取食材（数据库）→ 做好菜端回顾客（返回响应）→ 顾客看到页面。

## 4. 跟着做

需要安装 4 样东西（都免费）：

1. **VS Code**：写代码的"专用笔记本"。到 code.visualstudio.com 下载安装，全程默认选项即可。
2. **Node.js**：让电脑能"运行 JavaScript"的引擎。到 nodejs.org 下载 **LTS（长期支持）版**安装。
   - 补充解释：JavaScript 本来只能在浏览器里跑，Node.js 让它也能在你自己电脑上当"后端"运行，这样我们只学一种语言就能同时写前端和后端。
3. **Git**：代码的"存档工具"。到 git-scm.com 下载安装，默认选项一路下一步。
4. **注册一个 GitHub 账号**：github.com（第 4 步和第 10 步会用到，它是代码的"云盘 + 展示柜"）。

认识**终端（命令行）**：它是"用打字给电脑下命令"的地方。
- Windows：在开始菜单搜 "PowerShell" 或 "终端" 打开；也可以在 VS Code 里点菜单 `终端(Terminal) → 新建终端`，这样命令就直接在项目文件夹里执行，最方便。

安装完后，在终端逐条输入下面的命令（每输入一行按一次回车），用来确认装好了：

```
node -v
npm -v
git --version
```

逐行解释：
- `node -v`：查看 Node.js 版本，能显示版本号（如 v20.x.x）就说明装好了。
- `npm -v`：npm 是 Node.js 自带的"软件商店/管家"，后面我们用它下载别人做好的工具（库）。
- `git --version`：查看 Git 版本。

## 5. 检查一下

让小白把终端显示的三行版本号发给你核对。三条都出现版本号 = 环境就绪；若提示"不是内部或外部命令"，说明没装好或需要重开终端（安装后必须关掉终端重新打开）。

## 6. 学到了什么

1. 软件 = 前端（看得见）+ 后端（处理逻辑）+ 数据库（存数据），它们通过"接口"沟通。
2. VS Code 用来写代码，Node.js 用来运行 JavaScript，Git 用来存档，GitHub 是代码云盘。
3. 终端是用打字向电脑下命令的地方，命令输完按回车执行。

## 小白常见问题

- **Q：命令里的 `$`、`>` 要输入吗？** A：不用，那只是终端的"提示符"，只输入它后面的内容。
- **Q：npm 是什么、和 Node 是什么关系？** A：Node 是"运行环境"，npm 是随它一起装好的"包管理器"，专门用来下载和管理别人写好的现成工具。
- **Q：一定要装这么多吗？** A：是的，这四样是现代 Web 开发最基础的一套，装好后以后所有项目都能用。
