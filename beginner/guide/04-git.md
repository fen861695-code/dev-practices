# 第 4 步：学会存档——Git 入门

> 本步目标：理解版本管理的意义，学会用 Git 保存代码版本、查看历史，并把代码推送到 GitHub 备份。

## 1. 进度（导师话术）

"这一步给项目装上'存档点'。以后每完成一个功能就存一次档，搞砸了随时能回到上一个正常状态，再也不怕改坏代码。"

## 2. 为什么

- 没有版本管理，改坏了只能手动撤销，很容易把能用的代码弄丢。
- 每一次存档都记录了"什么时候、谁、改了什么、为什么"，是项目的完整成长日记。
- 推送到 GitHub 等于异地备份，还能让别人看到、协作。

## 3. 概念扫盲（游戏存档类比）

- **Git**：本地的"存档系统"，在你自己电脑上记录所有版本。
- **提交（commit）**：一次存档，给当前进度拍一张快照并附一句说明。
- **仓库（repository）**：被 Git 管理的项目文件夹。
- **暂存区（stage）**：拍照前的"取景框"——先决定哪些改动要进这次存档。
- **GitHub**：代码的"云盘"，把本地仓库同步到网上。
- **推送（push）/ 拉取（pull）**：把本地存档上传到云盘 / 把云盘的最新版本下载下来。

存档三步走（拍照类比）：`git add`（把要保存的改动放进取景框）→ `git commit`（按下快门存档）→ 需要时 `git push`（把相册备份到云盘）。

## 4. 跟着做

### （1）初始化仓库

在项目根目录（todo-app）终端输入：

```
git init
```

解释：让 Git 开始管理这个文件夹，会生成一个隐藏的 .git 目录存放所有版本信息，不要手动删它。

### （2）查看当前状态

```
git status
```

解释：查看哪些文件是新的、哪些被改动了、哪些已放进取景框。这是最常用的"我现在什么情况"命令，随时可以输入。

### （3）把改动放进取景框并存档

```
git add .
git commit -m "初始化项目：搭建 Express 服务器骨架"
```

逐行解释：
- `git add .`：`.` 表示"当前文件夹的全部改动"，把它们都放进暂存区。
- `git commit -m "..."`：正式存档，`-m` 后面引号里是这次存档的说明。说明要写清楚"这次做了什么"，方便以后回看。

### （4）查看存档历史

```
git log
```

解释：列出所有历史存档（谁、什么时候、说明是什么）。看完按 `q` 退出。

### （5）在 GitHub 建远程仓库并推送

1. 登录 GitHub 网站，点右上角 `+ → New repository`，仓库名填 `todo-app`，**不要**勾选 "Add a README"（本地已有内容），点创建。
2. 按 GitHub 给出的提示，在终端执行（地址用它显示的你自己的）：

```
git remote add origin https://github.com/你的用户名/todo-app.git
git branch -M main
git push -u origin main
```

解释：
- `git remote add origin 地址`：给远程云盘起个别名叫 origin 并记下地址。
- `git branch -M main`：把当前分支命名为 main（主线）。
- `git push -u origin main`：把 main 分支推送到云盘；`-u` 表示记住关联，以后直接输 `git push` 即可。

### （6）养成存档习惯

建议节奏：每完成一个能运行的小功能（比如"页面写好了""获取接口通了"），就走一次 add → commit；一天工作结束前 push 一次。
提交说明推荐写法：用"做了什么"开头，如 `feat: 完成待办添加功能`、`fix: 修复删除后列表不刷新`。

## 5. 检查一下

让小白执行 `git log` 并截图（能看到一次或多次提交），再到 GitHub 仓库页面刷新确认文件已出现在网上。

## 6. 学到了什么

1. Git 是本地存档系统，GitHub 是代码云盘；commit 是存档，push 是上传备份。
2. 存档三步：add（选改动）→ commit（写说明存档）→ push（备份到云端）。
3. 小步提交、说明清晰，是专业开发的基本习惯。

## 7. 记到项目文档

在 `PROJECT_JOURNAL.md` 记录：第一次 commit 做了什么、GitHub 仓库地址、对"暂存区/提交/推送"的理解。

## 小白常见问题

- **Q：一定要用命令行吗？** A：初学也可以用 "GitHub Desktop" 这类图形界面，按钮就是 add/commit/push；但理解命令行原理后，界面工具用起来更明白。
- **Q：commit 说明可以随便写吗？** A：技术上可以，但请写"做了什么"，未来的你会感谢现在认真写说明的自己。
- **Q：push 提示要登录怎么办？** A：按提示在弹出窗口登录 GitHub，或使用第 0 步装好的 gh 工具执行 `gh auth login` 完成授权。
