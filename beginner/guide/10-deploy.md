# 第 10 步：让别人能访问——发布上线

> 本步目标：理解部署的概念，使用零基础友好的免费托管平台把项目发布到公网，获得一个任何人都能打开的网址，并完成上线验证。

## 1. 进度（导师话术）

"到目前为止项目只在你自己电脑上能打开。这一步我们把它'搬到一直营业的商业街'，让全世界都能通过一个网址访问你的作品。"

## 2. 为什么

- 软件做出来就是给人用的，部署上线是价值交付的最后一公里。
- 亲手部署一次，你会真正理解"网址背后是一台一直运行的服务器"。

## 3. 概念扫盲（开店类比）

- **部署（deploy）**：把代码和运行环境放到一台一直开机、联网的服务器上运行。
- **服务器 / 主机**：云上一台 24 小时运行的电脑。
- **端口**：服务器上的"门牌号"，一台服务器可通过不同端口提供不同服务。
- **环境变量**：在服务器上配置的值（如端口号、数据库路径），代码通过 `process.env` 读取，避免把环境差异写死在代码里。
- **域名**：网站的地址名字，背后指向某台服务器。
- 免费托管平台（如 Render、Railway）能连接你的 GitHub 仓库，推送代码后自动构建、部署，对初学者最友好。

## 4. 跟着做

### （1）让代码适配云端环境

服务器端口要听从平台分配，修改 server.js 启动部分：

```javascript
const PORT = process.env.PORT || 3000;
app.listen(PORT, () => {
  console.log('服务器已启动，端口：' + PORT);
});
```

解释：平台会通过环境变量 PORT 指定端口，`process.env.PORT || 3000` 表示"有就用平台的，没有就用 3000"，本地和云端都能跑。

确保 SQLite 文件路径也可配置（平台文件系统可能是临时的）：

```javascript
const path = require('path');
const dbPath = process.env.DB_PATH || path.join(__dirname, 'data', 'todos.db');
const db = new Database(dbPath);
```

### （2）确认启动命令与 Node 版本

- package.json 里确认有（或补上）启动脚本：`"start": "node server.js"`。
- 在 package.json 中声明 Node 版本（engines），与本地 LTS 一致。

### （3）用免费平台部署（以 Render 为例，其他平台流程类似）

1. 打开 render.com，用 GitHub 账号登录并授权。
2. 选择 `New → Web Service`，选中你的 todo-app 仓库。
3. 填写配置：
   - Runtime / 语言：Node
   - Build Command（构建命令）：`npm install`
   - Start Command（启动命令）：`npm start`
4. 点击 Create / Deploy，平台会自动拉取代码、安装依赖、启动服务，并实时显示构建日志。
5. 部署成功后，平台分配一个公网网址（形如 https://todo-app-xxxx.onrender.com），打开即可使用。

### （4）上线验证（冒烟测试）

在公网网址上走一遍核心流程：添加 → 勾选完成 → 刷新确认数据在 → 删除。确认和本地行为一致。

### （5）了解限制与进阶（如实告知）

- 免费层服务在一段时间没人访问后可能"休眠"，再次打开会慢一点重新启动，用于学习和演示完全够用。
- 部分免费平台的磁盘是临时的，SQLite 文件在重新部署后可能重置。要长期可靠保存数据，进阶做法是使用平台提供的托管数据库（通过环境变量配置连接地址），这是后续学习方向。
- 纯静态页面（只有前端）还可用 GitHub Pages 免费托管；本项目含后端，需要用支持后端的平台。

## 5. 检查一下

让小白把公网网址和成功使用的截图发来。能在别人电脑/手机上打开并使用 = 部署成功。

## 6. 学到了什么

1. 部署 = 把项目放到 24 小时运行的云服务器；现代平台能连 GitHub 自动部署。
2. 用环境变量适配端口、路径等环境差异，代码本地与云端通用。
3. 免费层适合学习演示；生产级数据持久化需要托管数据库等更稳的方案。

## 小白常见问题

- **Q：构建失败怎么排查？** A：平台的构建日志会显示具体错误（常见：没装依赖、启动命令不对、Node 版本不符），把日志里的报错完整发来。
- **Q：部署后数据库里的数据会一直在吗？** A：取决于平台磁盘是否持久；免费演示环境可能在重新部署后重置，长期项目请接入托管数据库。
